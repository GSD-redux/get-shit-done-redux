**Projects using the bracket phase-ID convention now have their ROADMAP read correctly** — `roadmap analyze`/`get-phase`, the W005/W006/W007 phase checks, `validate health`, and both `total_phases` derivations previously matched only the `Phase N:` spelling and the `NN-name` directory shape, so on a bracket project every phase was invisible: `phase_count` and `total_phases` fell back to the on-disk directory count, `get-phase` reported not-found, every `GSD.02-05-slug` directory was reported malformed, and a completed milestone was warned to have unstarted phases. Milestone scoping now also recognises the ADR-canonical `## [GSD.02] Foundation` heading and applies to the phase DIRECTORIES too, so a bracket project's `completed_phases`, `total_plans`, `completed_plans` and progress percent are counted from the phases of the milestone STATE.md asserts rather than from every directory on disk. `roadmap analyze` resolves those directories too, so each bracket phase reports its real `disk_status`, `plan_count` and `summary_count` instead of `no_directory` and zeros, and a bracket icebox item listed in the checklist index no longer trips a `validate consistency` missing-directory warning that `validate health` does not raise. Retired bracket phases leave the denominator, and backlog phases are excluded from every count on a bracket project — both the bracket-sentinel milestones (`[GSD.999]` icebox, `[GSD.00]` pre-milestone) and the engine's reserved `0`/`999` phase tokens, so `roadmap analyze` and `state json` report the same number. Each widened read is SELECTED by the project's `phase_id_convention`, so a project that has not opted in compiles the same patterns it did before and is unaffected. `validate health` additionally gains an advisory W021 for bracket phases whose milestone disagrees with their enclosing section, likewise only for projects that have opted in. (#2761)
