**A context compaction no longer permanently disables context-warning escalation** — the monitor's per-session warn sentinel survived `PreCompact`, so once the first CRITICAL of a session had fired, `lastLevel` stayed pinned at `critical` for the rest of the run. That killed two documented behaviours at once (`docs/context-monitor.md`): the first warning of the post-compaction cycle was debounced instead of firing immediately, and the WARNING → CRITICAL escalation bypass — computed as "the previous level was WARNING" — could never be true again, so every later CRITICAL waited out the full five-tool-use debounce, precisely when an immediate warning matters most. The sticky `criticalRecorded` flag had the same shape: if a session compacted and later genuinely ran out, the `/gsd:resume-work` breadcrumb (#1974) still described the earlier near-miss rather than the exhaustion that ended the run. The hook was already wired to `PreCompact` (#772), but read the event only at the very end, and solely to choose an output envelope. It now clears the sentinel on that event and returns — before the metrics read, because a post-compaction reading is healthy again and the stale/above-threshold branches would otherwise exit first and never reach the reset. Returning early also stops the compaction from consuming a debounce slot of the cycle it was meant to restart. Non-compaction lifecycle events are unchanged: their side effects still run and their output stays silent (#2289). (#3709)
