**`gsd-tools query state.advance-plan` no longer increments a stale plan position and reports it as success** — the verb derived `Plan: X of Y` entirely from `## Current Position` prose, guarded it with a syntactic `isNaN` check only, and never consulted the plans on disk. A well-formed but drifted `2 of 8` was incremented, written back, and returned as `{"advanced": true, "current_plan": 3, "total_plans": 8}` for a phase holding twelve summarized plans — while `query phase-plan-index`, in the same binary on the same tree, reported all twelve. The same unchecked pair also fed the phase-completion decision, so drift could withhold `ready_for_verification` from a finished phase or declare it on an unfinished one. The verb now cross-checks the prose against the real plan set (via the existing `listMilestonePhaseDirs` + `matchPhaseDirs` + `scanPhasePlans` owners) and, on disagreement, refuses to mutate and reports `{"advanced": false, "reason": "position_diverged", "prose": {...}, "disk": {...}}`. The refusal is also announced on stderr as a `[gsd-tools] WARNING:` line naming both positions and the repair path — the two first-party callers (`workflows/execute-plan.md`, `agents/gsd-executor.md`) run the verb bare, discarding stdout and never testing the exit code, so a stdout-only refusal was a silent non-write; both now read `--pick reason` and stop on `position_diverged` instead of recording progress and a metric against a position that did not move — keyed on the reason rather than on `advanced`, because `advanced: false` is also the ordinary last-plan answer (`reason: last_plan`). And the verb now rejects unrecognized input instead of silently discarding it — options, short options and bare operands alike, with `--` honored as the POSIX end-of-options marker so what follows it is rejected as an operand rather than mislabelled an option. (#3830)
