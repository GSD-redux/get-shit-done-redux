**`gsd-tools query state.advance-plan` no longer increments a plan position that provably disagrees with the plans on disk, and no longer reports that as success** — the verb derived `Plan: X of Y` entirely from `## Current Position` prose and checked only that the prose was well-formed and agreed with itself — never that it agreed with the plans on disk, which it did not read at all. A well-formed but drifted `2 of 8` was incremented, written back, and returned as `{"advanced": true, "current_plan": 3, "total_plans": 8}` for a phase holding twelve summarized plans — while `query phase-plan-index`, in the same binary on the same tree, reported all twelve. The same unchecked pair also fed the phase-completion decision, so drift could withhold `ready_for_verification` from a finished phase or declare it on an unfinished one. The verb now cross-checks the prose against the real plan set (via the same raw phase-directory listing `query phase-plan-index` reads, plus the `matchPhaseDirs` and `scanPhasePlans` owners, so the two verbs cannot select different directories or count them differently) and, on disagreement, refuses to move the counter and reports `{"advanced": false, "reason": "position_diverged", "prose": {...}, "disk": {...}}`. That refusal fires when the verb is about to MOVE the counter; on the phase-complete branch a diverged counter is reported as untrusted rather than refused, because #4067 (merged while this was in review) decides that branch from the plans on disk — every plan summarized completes the phase, anything less declines the whole write as `plans_outstanding` — and that disk answer is the better guard there: it says whether the phase IS complete, where counter agreement only says whether the line is self-consistent, and refusing ahead of it would turn #4067's own case (a stale `7 of 7` carried into a fresh 3-plan phase) into a stop for every executor in a wave. The stale line is still announced on stderr with the same numbers and repair path, and a `last_plan` answer reached that way carries it as `"prose_diverged": {"prose": {...}, "disk": {...}}`. The refusal is also announced on stderr as a `[gsd-tools] WARNING:` line naming both positions and the repair path — the two first-party callers (`workflows/execute-plan.md`, `agents/gsd-executor.md`) run the verb bare, discarding stdout and never testing the exit code, so a stdout-only refusal was a silent non-write; both now read the verb's own answer and record progress and metrics ONLY on the three shapes that mean this plan's work is done — `advanced: true`, the ordinary last plan (`advanced: false` with `reason: last_plan`), and #4067's `plans_outstanding` (this plan done, sibling plans still executing; the last executor to finish completes the phase) — with an explicit instruction to halt the step rather than continue on anything else. That is an allow-list rather than a deny-list on purpose: a refusal, an exit-0 `{"error": ...}`, a reason the verb grows later, and a non-answer (a crash or missing binary leaves the capture empty) all stop, so the silent-skip class cannot be re-opened by an answer shape the callers were never taught. Keyed on the reason, never on `advanced` alone: `advanced: false` is also the ordinary last-plan answer (`reason: last_plan`), so branching on it would have skipped the final plan's recording on every phase. And the verb now rejects unrecognized input instead of silently discarding it — options, short options and bare operands alike — through `parseNamedArgsOrExit`, the canonical argv owner every other arm of the state router already uses, so this verb carries one usage contract and one `ERROR_REASON.USAGE` code rather than a second set of its own. The cross-check is deliberately narrow, and this is the scope to read the headline against: divergence is claimed ONLY from a completed plan scan that found at least one plan. A phase that cannot be resolved — not named by `## Current Position`, matched by no directory on disk, or ambiguous across several matching directories (the same token `query phase-plan-index` refuses to answer) — an incomplete scan, and a phase with no plan files on disk at all are treated as *no evidence*, not as divergence, and still advance exactly as before; blocking on them would strand projects the check knows nothing about. "No plan files at all" means neither live nor superseded: the presence test reads both counts, because guarding on the live count alone made a phase whose plans are every one of them `status: superseded` look identical to a phase between `begin-phase` and its first written plan, and abstaining there incremented the stale prose — this fix's own defect, found in review. A prose total matching *either* disk count is likewise accepted, live or including superseded, because the two commands that write that total disagree about supersession and a writer disagreement is not project drift. The position itself is range-checked against the same plan set, not just the total: `Plan: 20 of 12` against twelve plans on disk agrees on the total and is still a divergence — `0 of 12` is refused on the increment branch, and `20 of 12`, which sits on the completion branch, is reported as untrusted while the plans on disk decide whether the phase is complete (before this fix it satisfied `currentPlan >= totalPlans` and declared the phase `ready_for_verification` from a position provably outside the plan set; a negative position no longer reaches this check at all — #3791 made the position grammar unsigned, so it is refused as an unreadable shape further up). The bound is the count *including* superseded, so an all-superseded phase positioned past the live count is not mistaken for drift.

**Breaking, and worth calling out separately from the refusal:** because the callers now stop on anything that is not one of the three recording shapes, an exit-0 `{"error": ...}` from `advance-plan` halts the execute step where it previously fell through to `state.update-progress` and `state.record-metric`. That is the intended direction — a frozen counter should not be silent — but it is a behaviour change in its own right, and it applies to every error shape the verb can answer with, including the two ambiguity refusals (`ambiguous_position_phase`, `ambiguous_plan_position`) and any reason added later. The landing-order caveat this paragraph used to carry is spent: it warned that #3784 made the hybrid `Current Plan: N of M` shape unparseable and would therefore halt those projects until a fix landed. #3791 has since merged, the hybrid shape parses, and #3784 is closed — so that particular producer is gone and no interval remains to plan around.
