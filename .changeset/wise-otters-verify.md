**`gsd-tools query state.advance-plan` no longer increments a plan position that provably disagrees with the plans on disk, and no longer reports that as success** — the verb derived `Plan: X of Y` entirely from `## Current Position` prose, guarded it with a syntactic `isNaN` check only, and never consulted the plans on disk. A well-formed but drifted `2 of 8` was incremented, written back, and returned as `{"advanced": true, "current_plan": 3, "total_plans": 8}` for a phase holding twelve summarized plans — while `query phase-plan-index`, in the same binary on the same tree, reported all twelve. The same unchecked pair also fed the phase-completion decision, so drift could withhold `ready_for_verification` from a finished phase or declare it on an unfinished one. The verb now cross-checks the prose against the real plan set (via the existing `listMilestonePhaseDirs` + `matchPhaseDirs` + `scanPhasePlans` owners) and, on disagreement, refuses to mutate and reports `{"advanced": false, "reason": "position_diverged", "prose": {...}, "disk": {...}}`. The refusal is also announced on stderr as a `[gsd-tools] WARNING:` line naming both positions and the repair path — the two first-party callers (`workflows/execute-plan.md`, `agents/gsd-executor.md`) run the verb bare, discarding stdout and never testing the exit code, so a stdout-only refusal was a silent non-write; both now read the verb's own answer and record progress and metrics ONLY on the two shapes that actually moved the phase forward — `advanced: true`, and the ordinary last plan (`advanced: false` with `reason: last_plan`) — with an explicit instruction to halt the step rather than continue on anything else. That is an allow-list rather than a deny-list on purpose: a refusal, an exit-0 `{"error": ...}`, a reason the verb grows later, and a non-answer (a crash or missing binary leaves the capture empty) all stop, so the silent-skip class cannot be re-opened by an answer shape the callers were never taught. Keyed on the reason, never on `advanced` alone: `advanced: false` is also the ordinary last-plan answer (`reason: last_plan`), so branching on it would have skipped the final plan's recording on every phase. And the verb now rejects unrecognized input instead of silently discarding it — options, short options and bare operands alike, with `--` honored as the POSIX end-of-options marker so what follows it is rejected as an operand rather than mislabelled an option. The cross-check is deliberately narrow, and this is the scope to read the headline against: divergence is claimed ONLY from a completed plan scan that found at least one plan. A phase that cannot be resolved — not named by `## Current Position`, absent from the current milestone, or ambiguous across several matching directories — an incomplete scan, and a phase with no plan files written yet are all treated as *no evidence*, not as divergence, and still advance exactly as before; blocking on them would strand projects the check knows nothing about. A prose total matching *either* disk count is likewise accepted, live or including superseded, because the two commands that write that total disagree about supersession and a writer disagreement is not project drift.
